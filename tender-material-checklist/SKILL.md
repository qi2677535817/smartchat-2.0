# 招标文件材料清单提取

## 核心原则（必须先读）

本技能的唯一使命：从招标文件中提取**完整且准确**的应交材料/资质清单。

三条铁律，优先级从高到低：

1. **不能少**：招标文件中每一处明确要求"提供/出具/提交"的材料和资质，无论出现在哪个章节（资格要求、评分细则、无效投标条款、格式章节、技术规范、商务条款），都必须进清单。禁止只看目录、只看"投标人资格要求"一节就下结论。
2. **不能多**：清单中每一项都必须能在招标文件中找到**逐字原文依据**。原文没要求的就是不需要的，凭经验、惯例、其他项目模板添加的内容一律视为错误。示例：招标文件没让提供 ISO9001，即使行业惯例要提供，也不能进清单。
3. **不能错**：每项必须原样保留原文表述（尤其是材料名称、份数、盖章、有效期、时间范围等限定词），并标注出处（章节名+页码/条款号）便于人工回验。意思相近但限定条件不同的两条要求（如"近三年"与"近五年"业绩）禁止合并抹平差异。

宁可慢，不可错。凡是不确定的，标记为"待确认"并提问，绝不猜测。

## 工作流程

### 阶段 1：文件导入与文本化

- 接受 PDF、DOCX/DOC、TXT、图片（扫描件）等格式。
- PDF：优先使用可用的 PDF 技能/脚本提取全文文本，同时记录页码。
- Word：使用可用的文档读取能力提取全文，按章节结构保留层级。
- 扫描件/图片 PDF：提取不到文本时，明确告知用户"该文件为扫描件，无法保证逐字准确"，请用户提供可复制文本的版本或人工粘贴关键章节；在得到文本前不要产出清单。
- 文本化后先快速统计：总页数/字数、章节目录结构。若文本异常截断或乱码，先修复再继续，禁止基于残缺文本出清单。

### 阶段 2：全文结构定位

通读全文（长文档用 `scripts/scan_keywords.py` 先扫一遍定位，再精读命中区域），在心中建立招标文件地图，至少定位以下 6 类区域，并记录各自的页码范围：

| 区域 | 常见章节名关键词 |
|---|---|
| A. 资格要求 | 投标人资格要求、资格审查、供应商资格、投标人须知前附表 |
| B. 评审办法 | 评标办法、评审标准、资格性审查、符合性审查、评分细则、技术评分、商务评分 |
| C. 投标文件组成 | 投标文件组成、投标文件格式、应提交的资料、投标文件编制要求 |
| D. 否决/无效条款 | 投标无效、否决投标、视为无效、拒绝、废标、不予以受理 |
| E. 技术要求 | 技术要求、技术规范、技术参数、货物需求、服务需求 |
| F. 商务条款 | 交货期、工期、质保期、付款方式、售后服务、其他要求 |

注意：很多招标文件存在重复分布，同一材料可能同时出现在"须知前附表""评分细则""格式章节"三处。提取指南见 `references/extraction-guide.md`，处理前必须加载该文件。

### 阶段 3：逐条提取

对 A–F 每个区域逐段精读，凡出现"提供/出具/提交/附/附上/须具备/应具备/持有/加盖公章"等要求表述的句子，提取为一条候选条目。每条必须包含：

- **材料/资质名称**：用招标文件原文命名，不得改写简称。
- **要求原文**：逐字摘录该句话（可截取关键句，但限定词一个都不能丢）。
- **出处**：章节名 + 页码或条款号（如"第二章 3.1 条，第 12 页"）。
- **强制级别**（三选一，按原文用词判定）：
  - `强制`——不提供即无效投标/无法通过资格审查/符合性审查（原文含"必须/须/应/否则无效/否决"等）
  - `评分`——不提供不扣资格分但影响得分（出现在评分细则中）
  - `待确认`——表述模糊（如"如有可提供""建议提供"、指代不明），单独列出并向用户提问，禁止自行归类
- **形式要求**：正本/副本份数、盖章/签字要求、原件或复印件、电子件、有效期（如营业执照须在有效期内、审计报告须为近X年）、出具机构（如"由会计师事务所出具"）。

### 阶段 4：双向核对（质控核心，不可跳过）

**正向——查漏：**
1. 重新按 `references/extraction-guide.md` 的"高频易漏点清单"逐项自查：资格声明函、授权书、保证金凭证、信用记录截图、社保/纳税、无重大违法声明、中小企业声明函等常藏在格式章节或无效条款里的项目是否已捕获。
2. 用 `scripts/scan_keywords.py` 对全文再跑一遍关键词扫描，将命中行与已提取清单对照，凡命中但未入清单的行逐条判断：是漏了、还是属于非材料类要求（如格式要求、报价要求）并说明理由。
3. 检查评分细则中每一条打分点：有打分点通常就有对应证明材料，逐条反问"评委凭什么给这一分"，答不上来的说明漏了。

**反向——查多、查错：**
1. 清单中每一项回查原文出处，确认原文确实要求"提供"，且材料名称、数量、时间范围、盖章要求与原文完全一致。找不到原文依据的条目立即删除。
2. 同一材料多处出现的，合并为一条并罗列全部出处；合并时若各处限定条件不一致（份数不同、年份不同），保留最严格要求并在备注中写明差异，不得抹平。
3. 检查有无把"招标人要求自己做的事"误当成"投标人要提供的材料"（如"招标人组织踏勘"不是材料）。

### 阶段 5：输出交付（默认走交互式复核工具）

**首选路径：生成单文件离线 HTML 复核工具**（源文档为 PDF 时）。规范见 `references/review-tool-spec.md`，执行步骤：

1. **录入条目库**：把阶段 3 提取的条目整理为 JSON（字段见 `references/review-tool-spec.md` 第四节）。每条必须有 `anchor`（短、唯一、不跨页的原文片段，用于坐标定位）。
2. **生成工具**：
   ```bash
   python scripts/build_review_html.py --pdf <招标文件.pdf> --items <items.json> \
          --out <项目>_材料清单复核.html --vendor <含 pdf.min.js 与 pdf.worker.min.js 的目录>
   ```
   脚本自动完成：页码校准（offset 投票）、锚点坐标定位、覆盖度校验、单文件打包（内嵌 PDF＋pdf.js）。
3. **读生成报告，必须处理三类异常**：
   - `MISS`：锚点未匹配 → 修正 anchor 文本后重跑（不要放着不管）；
   - `AMBIG`：同句多处出现 → 在 items 中加 `page` 字段指定目标物理页（报告会列出候选页）；
   - `OK+容错`：表格页跨列干扰，已用字符级容错匹配通过，属正常。
4. **几何验证（必须，条目与"未覆盖语句"两套 rects 都要验）**：
   ```bash
   python scripts/verify_rects.py --pdf <招标文件.pdf> --items <项目>_items.json --report <项目>_高亮框验证报告.txt
   ```
   要求 **PASS 率 100%，且 SKIP（无定位）必须为 0 或在报告中逐条说明**。任一 FAIL（覆盖 <99.9%）说明高亮框没框住原文，必须修正后重跑，不得交付。
   未覆盖语句的 rects 在 HTML 的 `window.__UNCOVERED__` 中，可提取为同结构 JSON 后用同一脚本验证。
5. **自检内联脚本（防白屏）**：从 HTML 中抽出最后一个 `<script>` 块，用 `node --check` 验证语法；并确认无残留 `@@` 占位符。
6. **前端逻辑自检（沙箱内无法开浏览器时必做）**：
   ```bash
   node scripts/test_frontend_logic.js <项目>_材料清单复核.html
   ```
   校验排序（按页码／按分类）、"未覆盖语句→加入条目"、材料名称推断，退出码必须为 0。
7. **交付并说明**：把 HTML 交给用户，告知操作方式——条目默认按页码升序（可切按分类）、点条目/未覆盖语句定位并高亮、未覆盖语句可"定位高亮／加入条目／忽略"、导出需全部条目确认。若沙箱无法启动浏览器，明确告知用户"渲染/点击/导出"需其本机双击实测。

**降级路径**：用户只要静态清单、或源文档不是 PDF（Word/扫描件）时，输出 Markdown 清单（用户要求 Excel 时生成 xlsx），列固定为：

| 序号 | 材料名称 | 招标文件原文要求 | 出处（章节/页码） | 强制级别 | 份数/形式/盖章 | 我方是否具备 | 备注 |

其中"我方是否具备"留空供用户自查填写。

**两种路径都必须在文末附三段**：

- 「待确认项」：模糊/矛盾条款原文 + 疑问，等用户答复后更新清单；
- 「关键限定提醒」：有效期、时间范围、份数、盖章等容易出错的硬性限定；
- 「核对声明」：说明提取范围覆盖了哪 6 类区域、各自页码，供用户抽查验证。

提醒用户：清单基于招标文件文本提取，正式备标前请对照招标文件原件复核，重点关注"须知前附表"与"评标办法"两处。

## 效率约定

- 长文档（>50 页）先用 `scripts/scan_keywords.py` 定位命中页，再对命中区域精读，避免全文逐页通读浪费时间。
- 但"效率"永远让位于"准确"：扫描结果为零命中的关键词区域，仍需抽查目录级浏览确认，因为提取失败（乱码、表格文本化失败）可能导致关键词漏检。

## Resources

- `references/extraction-guide.md` — 招标文件六大区域的提取要点、强制性用词判定表、高频易漏点清单。**阶段 2 开始前必须加载。**
- `references/review-tool-spec.md` — 交互式复核工具规范（两栏布局、坐标高亮机制、条目数据结构、PDF 解析已知技术坑）。**生成 HTML 复核工具前必须加载。**
- `scripts/scan_keywords.py` — 招标文件全文关键词扫描定位脚本，用法：`python scan_keywords.py <招标文件.txt> [--context 1]`，输出命中行及行号，用于快速定位要求分布和阶段 4 查漏。
- `scripts/build_review_html.py` — 单文件离线复核工具生成器（坐标定位＋页码校准＋覆盖度校验＋内嵌 PDF 打包），用法见阶段 5。依赖 `pdfplumber`。
- `scripts/verify_rects.py` — 高亮框几何验证脚本：把每个高亮框区域从 PDF 裁出并提取文字，反向证明框内确为原文；分 PASS/SKIP/FAIL 三类统计，PASS 率必须 100% 且 SKIP 逐条说明才可交付。
- `scripts/test_frontend_logic.js` — 复核工具前端逻辑离线自检（最小 DOM 桩，无需浏览器）：验证条目排序、未覆盖语句"加入条目"、材料名称推断。用法：`node test_frontend_logic.js <复核HTML>`，退出码 0 为通过。**在浏览器不可用时，这是替代真机验证的关键手段。**
