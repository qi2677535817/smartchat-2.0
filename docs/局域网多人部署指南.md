# 局域网多人部署指南（≤5 人）

> 对应变更：`openspec/changes/harden-lan-multiuser`
> 适用场景：单台工作站部署，局域网内 ≤5 名同事同时使用；不使用容器（符合 PRD「明确不做」边界）。

## 1. 容量假设与已做的加固

| 项 | 假设值 | 对应加固 |
|---|---|---|
| 并发用户 | ≤ 5 | 单实例部署 + 反向代理 |
| 单份 PDF | ≤ 200 MB | 磁盘落盘 + `TENDER_MAX_UPLOAD_MB`（超限 413） |
| 同时提取任务 | ≤ 2 | `TENDER_MAX_CONCURRENCY` 并发闸门 + 排队 |
| 断线/刷新 | 结果不丢 | 任务驻留 + 「继续查看进度」 |
| 并发写数据库 | 不报 SQLITE_BUSY | SQLite WAL + busy_timeout 5s |

## 2. 前置依赖核验（逐条执行，任一失败先修复）

```powershell
# 2.1 Node（后端运行与构建）
node -v                      # 期望 v20 或更高

# 2.2 Python（PDF 管线依赖，必须可在 PATH 中直接以 python 调用）
python --version             # 期望 Python 3.11+

# 2.3 pdfplumber（管线实际使用的解析库）
python -c "import pdfplumber; print(pdfplumber.__version__)"

# 2.4 skill 目录是否就位（脚本 + pdf.js 资源）
Test-Path "$env:USERPROFILE\.workbuddy\skills\tender-material-checklist\scripts\build_review_html.py"
Test-Path "$env:USERPROFILE\.workbuddy\skills\tender-material-checklist\assets\vendor"
```

若 skill 不在默认位置，请改用仓库内副本并设置环境变量：

```powershell
$env:TENDER_SKILL_DIR = "F:\项目-实战\AI chat\smartchat-2.0\tender-material-checklist"
```

> **失败现象对照**：`python` 命令不存在时，接口会返回 **503「未检测到 Python 环境」**；skill 目录缺失时返回 **503「管线脚本缺失」**。

## 3. 构建

```powershell
# 后端
cd server
npm ci
npm run build            # 产物 dist/

# 前端
cd ..\client
npm ci
npm run build            # 产物 dist/，由 Nginx 托管
```

构建后请确认 `server/dist/main.js` 与 `client/dist/index.html` 存在。

## 4. 运行与守护（PM2）

```powershell
# 4.1 安装 PM2（仅首次）
npm i -g pm2

# 4.2 在仓库根目录执行
mkdir logs
pm2 start deploy/ecosystem.config.js
pm2 status                       # 应为 online

# 4.3 配置开机自启（Windows 建议配合 pm2-installer 或计划任务）
pm2 save
pm2 startup
```

**环境变量**（在 `deploy/ecosystem.config.js` 的 `env` 中调整）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 3000 | 后端端口 |
| `TENDER_MAX_UPLOAD_MB` | 200 | 单文件体积上限，需与 Nginx `client_max_body_size` 一致 |
| `TENDER_MAX_CONCURRENCY` | 2 | 同时执行的提取任务数，超出的排队 |
| `TENDER_SKILL_DIR` | `~/.workbuddy/skills/tender-material-checklist` | 管线脚本目录 |

## 5. 反向代理（Nginx）

复制 `deploy/nginx.conf.example`，替换其中的 `<仓库绝对路径>`，include 进 `nginx.conf` 的 `http {}` 块后 reload：

```powershell
nginx -t && nginx -s reload
```

**三个必须保留的配置**（去掉会导致「进度卡死」或「上传 413」）：

| 配置 | 值 | 原因 |
|---|---|---|
| `proxy_read_timeout` | `900s` | 默认 60s 会把 2–5 分钟的 SSE 长连接切断，前端进度条卡死 |
| `proxy_buffering` | `off` | 开启缓冲会攒着不发 `queued`/`progress` 事件 |
| `client_max_body_size` | `210m` | 需 ≥ 后端上传上限，否则大 PDF 在代理层就被拒 |

局域网同事访问地址：`http://<工作站IP>:8080`

## 6. 验收清单

- [ ] 上传一份 30 MB 真实招标 PDF → 正常生成复核界面
- [ ] 上传超过 200 MB 的文件 → 提示 413 与上限值
- [ ] 提取进行中**刷新页面** → 出现「有未完成的提取任务」并可持续查看进度直至完成
- [ ] 提取完成后重新进入页面 → 仍可从历史任务打开复核界面
- [ ] 3 人同时上传并提取 → 日志显示最多 2 个任务在跑，其余显示排队；全程无 5xx、无进程重启
- [ ] 服务进程被手动结束 → PM2 在 5 秒内自动拉起

## 7. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 接口返回 503「未检测到 Python 环境」 | PATH 中无 `python` 命令 | 安装 Python 3.11+，或改用 `python3` 并做软链；Linux 部署时注意后端 `spawn` 写死了 `python`（见下方遗留项） |
| 接口返回 503「管线脚本缺失」 | `TENDER_SKILL_DIR` 指向不存在路径 | 核对第 2.4 步路径，或设置 `TENDER_SKILL_DIR` |
| 进度条停在 30% 不动 | 反向代理超时切断 SSE | 确认 `proxy_read_timeout 900s` 与 `proxy_buffering off` 已生效 |
| 上传直接报 413 | 代理层体积上限过小 | 调大 `client_max_body_size` |
| 多人同时上传报 `SQLITE_BUSY` | WAL 未生效 | 确认 `data-cache/smartchat.db-wal` 存在；检查启动日志 |
| 磁盘被 `data-cache` 占满 | 产物无自动清理 | 定期清理 `server/data-cache/tender/`（保留 `smartchat.db`） |

### 已知遗留项（未在本变更处理）

1. **`spawn` 命令名写死为 `python`**：Linux 环境通常只有 `python3`，需设软链或改造为可配置（建议后续加 `PYTHON_BIN` 环境变量）。
2. **`synchronize: true`**：TypeORM 启动时自动改表结构，生产环境属反模式；并发规模继续扩大时应改为显式迁移。
3. **SQLite 单文件库**：不支持多实例水平扩展；并发用户数 > 5 时建议迁移 PostgreSQL（异步驱动）。
4. **产物无生命周期管理**：`data-cache/tender/` 只增不减，需外部定期清理或后续加清理任务。
